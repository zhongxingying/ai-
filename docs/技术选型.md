# 技术选型

| 层 | 选型 | 为什么 |
|---|---|---|
| 后端 | FastAPI | 异步 + 自动生成 API 文档 |
| ORM | SQLAlchemy 2.0 | 主流，配 Alembic 做迁移 |
| 数据库 | PostgreSQL + pgvector | 业务数据 + 向量数据一个库搞定 |
| 认证 | JWT | 无状态，不用存 session |
| Agent 框架 | LangGraph | 状态机式，循环和分支好控制 |
| LLM | OneAPI + qwen-turbo | 已有，便宜 |
| 前端 | 原生 HTML → Vue 3 | 先跑通，再升级 |
| 部署 | Nginx + uvicorn + systemd | 简单，可控 |

## 三个关键决策

1. **PostgreSQL + pgvector**：业务 + 向量一个库，不用维护两套
2. **LangGraph**：Agent 需要"循环 + 状态 + 条件分支"，它天生为这个设计
3. **原生 HTML 起步**：前端只是壳，接口跑通才是核心

## 不选什么

- 不用 Docker：部署时再说
- 不用 Kubernetes：过度设计
- 不用微服务：单体足够
